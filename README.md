# ArmCpu

ARM generic interrupt controller and timer.

## 1. What this is

`ArmCpu` is the kernel-side platform driver: `ArmCpu.cpp` (plus `Info.plist`, bundle
`org.blu-sharky.ArmCpu`) implements an `IOCPU` nub per core on top of `IOPlatformDevice`. It finds the
GIC distributor and redistributors and starts them, brings up the generic timer through
`enableCPUTimeBase()`, starts secondary cores (PSCI `CPU_ON` on this class of board), and sends and
services IPIs — either as SGIs or, on boards where `ICC_SGI1R_EL1` generates nothing, as
software-pended SPIs 1008+core (`armcpu-spi-ipi=1`).

It is a **kernel-stage** component: `build-arm-driver.py ArmCpu` emits `build/armcpu/libArmCpu.a`,
which the XNU link force-loads. Nothing of it runs in the firmware, and it is not a kext that loads
from the root volume — it is linked in.

Two board-specific notes, both recorded in the device repository:

- the pin `6288238` is a **short** hash and is not an object in a checkout of `UniXNU/ArmCpu`; the
  published content lives on the board's own `TongHuaQWQ/ArmCpu` — unverified from here;
- the board keeps a **local copy** at `macOS-ForUke/drivers/ArmCpu` because `feeds.py` resolves
  sources first-wins and a `git` entry cannot override a component the core carries as a submodule.
  The copy differs from this tree only by extra diagnostics (each `prepareGic()` step reports its own
  result and prints `IGROUPR0`/`ISENABLER0` for PPI 27), so a board whose timer never ticks can tell
  "never matched" from "`mapGic`/`initDistributor`/`wakeRedistributor` returned false".

What depends on it: every other kernel component that needs interrupts — storage, display, input, USB —
and the scheduler, which needs the timer tick and `signalCPU`. In the port's own record the kernel
reached kext startup but `ArmCpu::start()` was never called on uke, which is why the board copy carries
those probes.

## 4. Build and use

From the resolved build tree (the directory `unixnu tree` assembles, where this component appears as
`drivers/ArmCpu`):

```sh
python3 scripts/build-arm-driver.py ArmCpu        # emits build/armcpu/libArmCpu.a
```

The UniXNU driver does the same thing as part of `./unixnu build kernel`, because the device
repository names it as `component:ArmCpu` in `[kernel] archives`. When a workflow runs the archive
scripts itself it must export the kernel target first, exactly as `build-kernel-min.yml` does:

```sh
STATUS=$(./unixnu status --json -D ../macOS-ForUke)
export UNIXNU_XNU_ARCH=$(printf '%s' "$STATUS" | python3 -c 'import json,sys; print(json.load(sys.stdin)["board"]["arch"]["name"])')
export UNIXNU_IOS_VERSION=$(printf '%s' "$STATUS" | python3 -c 'import json,sys; print(json.load(sys.stdin)["board"]["os"]["ios_version"])')
python3 scripts/build-arm-driver.py ArmCpu
```

There is no host test suite in this repository; the checks are the compile and the kernel-side probes
it prints (`ArmCpu: …`, `armcpu_registered`, GIC register read-back), reported per hardware run in the
device repository's `porting.toml` (area `cpu`).

## Behaviour notes

`enableCPUTimeBase()` is the kernel entry the platform expert calls to arm the per-CPU timer; when the
kernel does not initialize the boot processor itself the driver calls `initCPU (true)` and enables the
boot core's GIC and timer. The IPI path is `signalCPU()`, with the software-SPI variant configured
group 1, edge-triggered, priority `0x80` and routed to the target core's affinity. Diagnostics counters
(`armcpu_timer_interrupts`, `armcpu_ipi_interrupts`, `armcpu_ipi_sent`, `armcpu_ipi_selftest_sent`)
exist for the probes above.

The working tree of this checkout may carry uncommitted instrumentation; the published pins are the
commits listed in section 2.
